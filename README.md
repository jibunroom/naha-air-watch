# naha-air-watch

那覇発の航空券セール情報を毎日集め、判定ラインを超えた「即買い」「安い」と、
那覇に就航している会社の「全路線セール」だけをメールで通知する。
構成は [nyusatsu-watch](https://github.com/jibunroom/nyusatsu-watch) を流用（GitHub Actions + Gemini + お名前.com SMTP）。

**最優先は「大事なセールを逃さない」**。そのための仕組み:

| 仕組み | 理由 |
|---|---|
| 航空会社の公式発表（ジェットスター・ピーチは PR TIMES、スカイマークは公式運賃表）＋まとめ4サイトの二重取得 | 片方が壊れても拾える。公式は発表が早い |
| RSS は既読に当たるまで最大3ページ遡る | TRAICY・sky-budget は1日の記事数が1ページに収まらない |
| 一次フィルタは那覇就航会社の「全路線」記事も通す | 全路線セールの記事には那覇の文字が無いことがある（実例あり） |
| Gemini はモデルを順に切り替える | 無料枠は1モデル1日20回。上限・混雑・廃止なら次のモデルへ |
| 抽出失敗・送信失敗した案件も捨てない | 要確認として通知／送れるまで持ち越し |
| 取得元ごとの故障検知 | 2回続けて取得できなければ警告メール |
| 1日2回（7時・18時） | 会員先行が13時間だけ、のような短いセールのため |

## 実行

```bash
python -m src.main --dry-run     # メール送信・保存なしで結果を画面に出す
python -m src.main               # 本番
python -m pytest -q
```

判定のしきい値・行き先・航空会社は `config/rules.yml`、取得元は `config/sources.yml` で変更できる。

## 取得元（2026-10-01 調査）

採用: ジェットスター（PR TIMES）／ピーチ（PR TIMES）／スカイマーク（公式運賃CSV・お知らせ）／
モノリビ（RSS・国内線一覧・国際線一覧）／TRAICY／sky-budget／LCCjp（dsk.ne.jp）

取れないもの: ジェットスター・ピーチ公式サイト（自動アクセスに無応答）、HIS（403）、
trip.com・agoda（robots.txt で航空券検索結果を禁止）、スカイスキャナー（運賃が HTML に無い）

## データ（data/、リポジトリにコミット）

記事の本文は保存しない（公開リポジトリのため）。保存するのは価格・路線・期間・URL だけ。

| ファイル | 中身 |
|---|---|
| seen.json | 既読記事（URLのハッシュ・取得日時） |
| sales.json | 通知済みセール（同じセールを二度通知しない） |
| history.json | 価格履歴（v2 で中央値ベースのしきい値に使う） |
| pending.json / undelivered.json | AI抽出・メール送信が失敗した分の持ち越し |
| health.json | 取得元ごとの連続失敗回数・日別件数 |
